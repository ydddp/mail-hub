认证方式

所有 /api/* 接口需在请求头中携带 Bearer Token。支持两种身份：

Authorization: Bearer your-token

管理员密钥（环境变量 API_SECRET）：拥有全部权限，包括密钥管理接口。

普通 API Key（通过管理员创建，mk_ 前缀）：可使用获准的公共接口，只能操作自己的邮箱。账号池、渠道配置、密钥管理和资产恢复等管理接口仅限管理员，普通 Key 调用返回 403。每次调用自动记录用量。

若未设置 API_SECRET 则无需认证（开发模式）。

错误处理

所有错误响应格式统一：

{
  "error": 错误描述信息
}

常见状态码：400 参数错误、401 未认证、404 资源不存在、409 资源冲突、410 资源已关闭、502 上游服务异常、503 全部渠道不可用。

邮箱管理

核心工作流：创建临时邮箱 → 轮询收信 → 提取验证码 → 上报结果 → 关闭邮箱。

POST /api/inbox 创建邮箱（自动调度或指定渠道）
请求体 (JSON)
参数类型必填说明
forstring是目标服务名（如 twitter.com），用于避开已封禁的域名。缺失返回 400
providerstring否指定渠道名（如 mailtm、outlook），不填则自动调度
domainstring否指定域名
subdomainstring否泛子域名前缀（仅 YYDS 渠道），如 team-a → user@team-a.example.com
aliasboolean否要一个子地址别名（账号+标签@域名）。标签由服务端生成，不要自己传。仅 Outlook 支持，其他渠道忽略——请以响应里的 address 为准
durationnumber否邮箱有效时长（秒），最小 60，最大 30 天；到期自动关闭并释放资源
needPollingboolean否是否要求渠道支持轮询收信，默认 true
响应 201
{
  "id": "aBcDeFgHiJkL",
  "address": "random@domain.com",
  "provider": "mailtm",
  "expiresAt": "2025-01-01T12:00:00Z",
  "features": { "pollInbox": true, "attachments": false, ... }
}
自动调度按「调度顺序」逐个尝试渠道，跳过已禁用、仅手动、限流/冷却中的；顺序可全局或按目标服务设置，用 GET /api/dispatch/preview 可预演。Outlook 渠道从账号池中分配。

GET /api/inbox/:id/code 自动提取验证码/链接
查询参数
参数类型必填说明
waitboolean否设为 true 会轮询等待邮件到达
timeoutnumber否等待超时（秒），默认 60，最大 120
typestring否按类型过滤：numeric、alphanumeric、link
selectionstring否latest / matching（仅 Outlook）
excludeMessageIdstring (repeat)否重复传入排除 ID：最多 20 项，每项 2048 UTF-16 代码单元，总 UTF-8 8192 字节；超限 400
sincestring/number否只提取此时间之后收到的新邮件，支持 ISO 时间或毫秒时间戳
响应 200
{
  "codes": [
    { "type": "numeric", "value": "483921",
      "confidence": 0.95, "context": 您的验证码是 483921 }
  ],
  "email": { "from": "...", "subject": "..." },
  "messageId": "message-123",
  "receivedAt": "2025-01-01T00:01:00Z"
}
典型集成方式：先 POST /api/inbox 创建邮箱 → 用邮箱注册目标服务 → GET /api/inbox/:id/code?wait=true&timeout=60 等待验证码。Outlook 多次取件用 selection=matching，并重复传入已返回的 excludeMessageId，保留同秒其他邮件。since 仍是严格时间下界。
匹配取码的扫描结果
仅 selection=matching 返回 scan；scope 为 inbox_and_junk。下列计数和上限由同一次请求的两个目录、重试及等待轮次共用。
参数说明
checked / pages / metadata已检查的候选详情数 / 已读列表页数 / 已读原始元数据条数；上限分别为 5 / 5 / 100。元数据在本地收件人过滤前计数。
complete当前候选窗口是否检查完，不代表整个邮箱；找到匹配但仍有未检查候选时也为 false。
truncated列表窗口尚未读完。达到上限时不能据此断言整个邮箱没有匹配。
partial读取被错误或截止时间等中断，结果不完整。
folders各目录的 folder 与 complete；一个目录读完不代表另一个也读完。
reasonmatched 找到匹配；window_exhausted 当前窗口无匹配；scan_limit 达到扫描上限；timeout 等待结束；读取错误的 429/502 响应带 error。
匹配成功时，email.recipientAddress 为 To/Cc 确认的本次邮箱地址，无法确认时为 null。详情读取失败不会降级用摘要取码；429 按 Retry-After 退避，其他读取失败返回 502，不能当作成功的空结果。
POST /api/inbox/:id/report 上报邮箱使用结果（成功/失败）
请求体 (JSON)
参数类型必填说明
successboolean是true 记录成功，false 记录失败（可触发自动封禁规则）
servicestring否目标服务名，用于统计和自动封禁规则匹配
响应 200
{
  "ok": true,
  "action": "block_recorded",
  "blocked": { "service": "twitter.com", "domain": "example.com" }
}
上报失败会记录日志。若管理员配置了自动封禁规则（如「某服务失败 3 次/24h 自动封禁」），达到阈值时域名会被自动封禁。
DELETE /api/inbox/:id 关闭邮箱

关闭后邮箱状态变为 closed，不再可用。Outlook 渠道会释放账号回池。

响应 200
{ "ok": true }

渠道管理

查询和配置邮箱渠道（Provider）。每个渠道可独立启用/禁用、选择是否参与自动调度；自动调度的先后顺序由下方的调度规则接口管理。

池化渠道说明
 Outlook：1:1 账号分配模式，每个邮箱独占一个 Outlook 账号，关闭后账号回池。容量 = 空闲账号数。
 YYDS Mail：多 API Key 池化模式（X-API-Key 认证），支持固定域名和泛子域名（wildcard）。每个 key 每日 20,000 次 API 调用配额，按 key 轮转分摊负载。邮件 24 小时自动删除。上游 API 文档：maliapi.215.im/v1/llms.txt

GET /api/dispatch/preview 预演自动调度：这一单会按什么顺序试、谁会被跳过
查询参数
参数类型必填说明
forstring否目标服务；不填则按全局顺序
needPollingboolean否默认 true；为 false 时不跳过不支持轮询的渠道
纯本地计算，不调用任何上游，不改任何状态。域名封禁在创建时才过滤，预演不包含。
响应 200
{
  "service": "twitter.com",
  "rule": { "source": "service", "others": "append" },
  "candidates": [
    { "provider": "outlook", "eligible": true },
    { "provider": "mailtm", "eligible": false, "reason": "cooldown",
      "cooldownReason": "rate-limit", "nextAvailableAt": "2026-10-12T09:15:00.000Z" },
    { "provider": "icloud", "eligible": false, "reason": "manual_only" }
  ]
}
source：service 有此服务的规则 / global 只有全局规则 / default 未保存任何规则（按信任度排）。
reason：unknown_provider 规则里的名字当前未注册（如模板已停用）、disabled、manual_only（自动调度关闭且未被此服务的规则点名）、no_polling、rate_limited、cooldown。
GET /api/dispatch/rules 列出调度顺序规则（管理员）
响应 200
{
  "defaultOrder": ["imap", "icloud", "outlook", "yyds", "mailtm", ...],
  "rules": [
    { "service": "*", "order": ["outlook", "imap", ...], "others": "append", "updatedAt": "..." },
    { "service": "twitter.com", "order": ["outlook", "icloud"], "others": "exclude", "updatedAt": "..." }
  ]
}
* 是全局顺序；没保存时用 defaultOrder（按信任度降序，同分按注册顺序）。规则里没列到的已注册渠道按注册顺序追加在末尾，新加的渠道不会悄悄不可达。某服务的规则列出的渠道排最前；others 为 append 时其余按全局顺序跟在后面，为 exclude 时只用列出的。被服务规则点名的渠道即使关闭了自动调度也会参与。
PUT /api/dispatch/rules/:service 保存某服务（或 * 全局）的调度顺序（管理员）
请求体 (JSON)
参数类型必填说明
orderstring[]是渠道名数组，第一个最先试；不能重复；必须是已知渠道（已注册、曾注册过、或原规则里已有）
othersstring否append（默认）或 exclude；对 * 恒为 append
响应 200
{ "service": "twitter.com", "order": ["outlook", "icloud"], "others": "exclude", "updatedAt": "..." }
DELETE /api/dispatch/rules/:service 删除规则（管理员）；删 * 即恢复默认顺序
响应 200
{ "ok": true }
GET /api/providers/:name/domains 获取渠道当前可用域名
响应 200

模板账号恢复

模板渠道已创建上游账号、但后续认证失败时，可在这里恢复并领取。以下接口仅限管理员；列表只返回状态和地址等元数据，不返回密码、token 或配置快照。

GET /api/template-providers/:name/recoveries 恢复记录列表
路径中的 name 是模板渠道名，id 是恢复记录 ID。记录中的 operationActive 表示操作进行中；canRetry / canClaim 表示当前资产是否具备重试 / 领取条件，领取时还会检查现用模板。
响应 200
{
  "recoveries": [
    {
      "id": "recovery-uuid",
      "provider": "mailtm",
      "phase": "auth_pending",
      "address": "user@example.com",
      "createdAt": "2026-11-09T00:00:00.000Z",
      "updatedAt": "2026-11-09T00:00:01.000Z",
      "expiresAt": "2026-11-10T00:00:00.000Z",
      "claimedInboxId": null,
      "lastStatus": 503,
      "operationActive": false,
      "canRetry": true,
      "canClaim": false
    }
  ]
}
phase：attempting 创建已开始；upstream_created 已保存上游账号；auth_pending 认证待完成；ready 可领取；claimed 已领取；outcome_unknown 创建结果未知，需人工核查。模板删除后仍可查看保留记录。
POST /api/template-providers/:name/recoveries/:id/retry 重试账号认证
无需请求体。沿用创建时保存的配置与账号，仅重试 postCreate 认证，不重新创建账号。操作进行中或结果未知返回 409；ready / claimed 重复调用直接返回当前记录。模板被修改、停用或删除后仍可恢复认证；认证成功不延长原到期时间。
成功返回 { "recovery": { ... } }，字段同列表记录。上游 HTTP 错误保留状态码；响应无效或缺少凭据返回 500。已知资产的错误响应同时带 error 与 recovery，修正原因后再重试。
POST /api/template-providers/:name/recoveries/:id/claim 领取已恢复账号
无需请求体。要求账号 ready、未过期，且现用模板已启用、关键配置与创建时一致；状态或模板不符返回 409，过期返回 410，均保留资产。创建的邮箱仅管理员可见，沿用原创建及到期时间；重复领取返回同一邮箱，不重复分配。
响应 200
{
  "id": "inbox-id",
  "address": "user@example.com",
  "provider": "mailtm",
  "expiresAt": "2026-11-10T00:00:00.000Z",
  "recovery": {
    "id": "recovery-uuid",
    "phase": "claimed",
    "claimedInboxId": "inbox-id"
  }
}

GET /api/outlook/accounts/:email/mailbox 查看账号邮箱的全部邮件
查询参数
参数类型必填说明
limitnumber否每页条数，默认 50，最大 100
pageTokenstring否返回的 nextPageToken，10 分钟失效
响应 200
{
  "email": "user@outlook.com", "limit": 50, "truncated": false,
  "nextPageToken": null,
  "messages": [
    { "id": "...", "from": "...", "subject": "...", "receivedAt": "...",
      "leaseId": "i-abc123", "leaseState": "lease" }
  ],
  "leases": [
    { "id": "i-abc123", "address": "user+tag@outlook.com", "targetService": "github",
      "createdAt": "...", "endedAt": null, "status": "active" }
  ]
}
管理员专用。/api/inbox/:id/messages 只返回该邮箱在这一次租期内收到的邮件，这条接口返回整个账号邮箱。每封邮件带 leaseState：lease（属于 leaseId 那次租期）、gap（两次租期之间，账号空闲）、before（第一次租期之前）、undated（没有可解析的时间）。limit 是每页条数，使用返回的 nextPageToken 作为 pageToken 加载更早邮件。状态 10 分钟失效；刷新获取新邮件。
收件归属与到达时段
参数说明
recipientMatchexact 确认一个收件地址；multiple 有多个不同收件地址；unknown 无可用证据。依据 To/Cc 或 IMAP envelope，不用主账号地址补猜。
recipientAddress仅 exact 时提供已确认的收件地址；其他情况不返回此字段。
leaseId / leaseState只描述邮件到达时落在哪段租期，不证明它寄给了该租期的地址。
旧别名的迟到信可以落在新租期内。列表与详情都提供这些归属字段；普通邮箱接口仍受收件人及租期隔离限制。同时间邮件按 ID 稳定排序，不代表真实投递先后。
GET /api/outlook/accounts/:email/mailbox/:messageId 读取账号邮箱中的一封邮件
响应 200
{
  "id": "...", "from": "...", "subject": "...",
  "receivedAt": "...", "text": "...", "html": "..."
}
管理员专用，不受租期限制。/api/inbox/:id/messages/:mid 对租期外的邮件返回 404，这条接口能打开它们。
DELETE /api/outlook/accounts 批量删除账号（仅未分配的）

iCloud 别名
隐藏邮件是转发别名，不是信箱：Apple 没有按别名读信的 API。所以这个渠道分两半——签发地址走 Apple 私有接口，收信走「转发目标信箱」的 IMAP。转发目标常常不是 Apple 信箱（Apple ID 用 gmail 注册时就得连 imap.gmail.com）。需要 iCloud+ 订阅；一个 Apple ID 一辈子 750 个地址，所以地址回收复用而不是用完即弃。
GET /api/icloud/accounts 列出所有 Apple ID
响应 200
{
  "accounts": [
    { "id": "uuid", "apple_id": "me@gmail.com",
      "region": "global", "auth_mode": "srp",
      "imap_host": "imap.gmail.com", "imap_user": "me@gmail.com",
      "status": "active", "last_error": null }
  ]
}
status 三态：active 两半都通；degraded 会话过期，池里现有地址照常收信但不能签发新的；error 收信不可用，调度会跳过。Cookie、Apple ID 密码、信任令牌、IMAP 密码一律不返回。
POST /api/icloud/accounts 添加 Apple ID
请求体
{
  "appleId": "me@gmail.com",
  "region": "global",
  "cookies": "<整坨粘贴>",
  "imapUser": "me@gmail.com",
  "imapPassword": "<应用专用密码>",
  "imapHost": "imap.gmail.com",
  "imapPort": 993
}
cookies 接受浏览器给的任何形式：复制为 cURL（任意 shell）、复制为 PowerShell、Cookie 扩展导出的 JSON、或纯 Cookie 请求头。缺 X-APPLE-WEBAUTH-TOKEN 或 X-APPLE-WEBAUTH-USER 会直接 400 并指名缺哪个，而不是存下来等以后失败。
POST /api/icloud/accounts/:id/test 同时检测签发与收信两半
响应 200
{
  "ok": false,
  "forwardTo": "me@gmail.com",
  "forwardMismatch": null,
  "hmeError": null,
  "imapError": "authentication rejected: ..."
}
两半的错误分开返回，因为它们在不同地方修：Cookie 归 Apple 网页，IMAP 密码归收信邮箱的服务商。forwardTo 是隐藏邮件实际投递到的信箱，跟 IMAP 登录名不一致时 forwardMismatch 会直说。
POST /api/icloud/accounts/:id/cookies 就地更换过期 Cookie
保留地址池。删号重建会把它持有的每一个别名一起烧掉——每个都占 750 名额中的一个。
POST /api/icloud/accounts/:id/srp/begin SRP 登录，用信任令牌取代 Cookie
请求体
{ "password": "<Apple ID 密码>" }
→ { "sessionId": "...", "needsMfa": true }
随后
GET  /api/icloud/srp/:sessionId/phones      // 可选：手机号列表
POST /api/icloud/srp/:sessionId/sms         { "phoneId": 1 }
POST /api/icloud/accounts/:id/srp/complete  { "sessionId": "...", "code": "123456" }
Cookie 几小时过期，信任令牌能撑很久，所以 6 位码是每个 Apple ID 输一次而不是每次会话输一次。Apple 认可已存的信任令牌时 needsMfa 为 false，根本不推码。会话 5 分钟过期；握手中间态在内存里，这期间重启会丢失，重新登录即可。手边没有苹果设备时用 phones + sms 走短信。
POST /api/icloud/accounts/:id/generate 立刻生成地址（手动补货）
请求体
{ "count": 1 }   // 最多 5
→ { "created": 1, "addresses": ["quiet.fox42@icloud.com"] }
常规路径是后台自动补货，这个是应急用的。Apple 拒绝时原样返回它自己的措辞——它的错误分类没有公开文档，不做臆测的归类。自动补货的开关和目标值在 iCloud 页面上，或走 PATCH /api/admin/settings 的 icloud_pool_enabled / icloud_pool_target（目标值钳到 750）。
GET /api/icloud/addresses 地址池
state 三态：free 在池中可领用；assigned 被某个活着的 inbox 持有；retired 已在 Apple 侧停用、永不再发，它占的名额也永久花掉了。
GET /api/icloud/addresses/:hme/messages 按地址读信（含 /:uid 详情）
这个地址收到过的所有邮件，不像 /api/inbox/:id/messages 会隐藏比 inbox 更早的信。用来回答「这个地址到底收到过东西没有」。
POST /api/icloud/addresses/:hme/retire 停用被烧掉的地址
在 Apple 侧关闭转发并永不再分配。有 inbox 正持有时返回 409。它占的那个名额不会还回来——750 是一个 Apple ID 一辈子的总数。

集成示例

典型验证码获取流程

// 1. 创建邮箱（自动选择最优渠道，避开封禁域名）
const inbox = await fetch('/api/inbox', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ for: 'twitter.com' })
}).then(r => r.json());
// → { id: "aBcDeFgHiJkL", address: "random@domain.com", ... }

// 2. 用邮箱地址去目标服务注册/验证

// 3. 等待并提取验证码
const code = await fetch(`/api/inbox/${inbox.id}/code?wait=true&timeout=60`)
  .then(r => r.json());
// → { codes: [{ type: "numeric", value: "483921", confidence: 0.95 }] }

// 4. 上报结果（喂给自动封禁规则和统计）
await fetch(`/api/inbox/${inbox.id}/report`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ success: true })
});

// 5. Close inbox
await fetch(`/api/inbox/${inbox.id}`, { method: 'DELETE' });
