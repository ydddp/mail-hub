one frontend get-code path. Both now support the approved Outlook matching
contract. The shared API client additionally preserves HTTP status for distinct
throttling and upstream-failure UI states. The extractor is unchanged.

`selection=matching` sequentially checks at most five candidate details in the
current list window, received-time descending with code-unit ID ties. It skips
successfully checked unmatched IDs across waiting rounds. Every awaited
operation is followed by owner, lease, assignment and recipient checks. Errors
stop the scan without summary fallback. The original latest path remains the
default; strict `since >` is unchanged. Invalid timeout values now return 400.
The deadline discards late results and prevents subsequent reads; it does not
cancel an already running provider operation. API documentation states this.
