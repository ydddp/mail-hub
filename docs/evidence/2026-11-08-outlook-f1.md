not another backend audit. The same-class census found nine affected sites:
two mail timestamp render sites, two message-list sorting sites, three mappings
that discarded recipient evidence (shared Graph/REST mapping and IMAP
list/detail), and two administrator serializers. All nine are handled.

Focusable/hoverable help shows the UTC ISO instant, including stored
milliseconds, and the viewer's timezone. Unknown time stays unknown. Both
message lists use receive-time descending and code-unit ID tie breaking;
equal timestamps imply no actual delivery order. Other configuration-table
time formatting is unchanged.

Graph/REST To/Cc and IMAP envelope evidence travel on an internal symbol, which
survives object spreads but is omitted by JSON serialization. Admin account
mailbox list/detail add `recipientMatch` and, only for one distinct address,
`recipientAddress`. Missing evidence stays unknown and multiple addresses are
not claimed by one lease. Ordinary owner-key HTTP list/detail responses remain
free of this evidence. Existing recipient filtering, lease lifetime checks,
429 handling, read budgets and latest-code semantics are unchanged.

`leaseId` / `leaseState` retain their temporal meaning. Admin rows separately
label recipient and arrival window; removed usage records are not recreated.
The minimal provider/base plumbing was necessary because the accepted R01 code
checked To/Cc but discarded them at the public-message mapping boundary. API
documentation describes the additive admin fields and their limitations.
