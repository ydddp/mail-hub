# Mail Hub 浏览器助手（Tampermonkey 脚本）

在注册网站时主动唤出一个小面板，用你自己的 Mail Hub 取一个临时邮箱、复制地址、读取验证码或验证链接，然后手动上报成功并关闭邮箱。

- 首个支持组合：**Chrome + Tampermonkey**。
- 两个安装来源：你的 Mail Hub（从哪台装就从哪台更新，默认也连它），或本仓库的 `userscript` 分支（跟随最新正式版本，服务地址自己填）。不上架扩展商店或公共脚本站。
- 不做：页面内输入框按钮、整张表单自动填写、自动提交注册、自动打开验证链接、对外发信。「填入」只在你点它时写一个框。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 二选一，Tampermonkey 会弹出安装页。两个地址都不需要登录，脚本里不含任何密钥。
   - 在 Mail Hub 后台「系统设置 → 浏览器助手」点「安装」，或直接打开 `https://<你的 Mail Hub>/userscript/mail-hub.user.js`。
   - 不方便登录那台 Mail Hub 的后台（比如你只拿到了一个 API Key）时，打开 <https://raw.githubusercontent.com/ydddp/mail-hub/userscript/mail-hub.user.js>。
3. 打开任意 http(s) 网站，按 **Alt+Shift+M** 唤出面板，或从 Tampermonkey 菜单点「打开 Mail Hub 邮箱助手」。
4. 第一次连接：
   - **服务地址**：从 Mail Hub 安装的，已预先填成那台 Mail Hub；从 GitHub 安装的是空的，自己填。要连别的实例可以改（默认按 HTTPS 解析，本机调试可以写 `http://localhost:3000`。http 地址指向别的机器（如局域网 IP）时，面板会提醒 Key 将明文经过网络；`localhost`、`127.0.0.1` 等本机地址不提醒）。
   - **API Key**：普通 `mk_...` 用户 Key 就够，**不需要管理员密钥**。
5. 点「连接」。脚本会先用这个 Key 请求一次 `GET /api/providers` 验证，失败会保留你填的内容并说明原因，不会保存坏配置。

密钥只写进脚本管理器的存储（`GM_setValue`），不写进目标网站的 localStorage、DOM、URL 或 `postMessage`。

## 使用

面板分两层：一条**胶囊**，永远只放「现在要用的那一个」（地址、验证码或验证链接）和对应的一个主按钮；点 ⌄ 展开下面的**抽屉**，里面是邮件、地址、完成操作和设置。

| 操作 | 说明 |
| --- | --- |
| 唤出 | `Alt+Shift+M`（可在设置里改），或 Tampermonkey 菜单。唤出总是显示胶囊并展开抽屉 |
| 获取邮箱 | 胶囊写着「用哪家提供商、为哪个网站」，点「获取邮箱」。创建后立即落盘地址并开始等待邮件，状态行显示已等多久 |
| 填入 | 胶囊或抽屉里的「填入」会自己找到网页上的邮箱框或验证码框写进去，不用先点输入框；分格验证码逐格填。找不到有把握的框就改为复制并提示，绝不写进密码框或手机号框。填完抽屉自动收起，被填的框会闪一圈 |
| 收到邮件 | 胶囊原地换成验证码（主按钮「填入验证码」）或验证链接的域名（「打开链接」）；两者都有时验证码为主，旁边的 ↗ 打开链接。多个候选码时不替你挑，抽屉自动展开让你选。没识别出验证码时提供「查看邮件」 |
| 注册成功并结束 | 填过验证码或打开过链接后，胶囊主按钮变成它（变化后 0.7 秒内不响应点击，防止连点误触）。先上报成功，确认后才关闭邮箱 |
| 只上报，继续收件 | 抽屉里的文字按钮，只上报成功，邮箱保留并继续收件 |
| 结束使用 | 只关闭邮箱，**不会**自动上报失败 |
| 换一个 | 抽屉地址行。确认后先关闭当前邮箱（不上报）再取新的 |
| 提供商 | 没有在用邮箱时在抽屉里选。「自动分配 · 按服务顺序」= 不发送 `provider`；手动选择只试这一家，**失败不会自动回退** |
| 服务标识 | 抽屉里显示从页面地址解析出的主域名，没有在用邮箱时可用铅笔改写并记住 |
| × | 收到屏幕边缘的小按钮，收件继续。收起时来了新邮件，小按钮上出现一个圆点，不会弹开或抢焦点 |
| 移动 | 拖胶囊空白处移动，靠近左右边缘会吸附；边缘小按钮拖动后贴到最近的竖边。位置按主域名记住，窗口变小时总会夹回可见范围（只有拖动才改写记住的位置） |
| 记住网站 | 唤出过的主域名记为「已启用」；以后访问时，有在用邮箱显示胶囊，否则只显示边缘小按钮 |
| 跟随跳转 | 同一个标签页里刷新、换页、甚至跳到别的网站（如第三方登录页），只要邮箱还在用，胶囊都会自动回来，已收到的验证码也还在；别的标签页不受影响。依赖脚本管理器的 `GM_getTab`/`GM_saveTab` |
| 多套连接 | 设置里「＋ 添加连接」，每套是「名称（可选）+ 服务地址 + API Key」，三者一起保存；添加前会先用这个 Key 验证一次。两套以上时抽屉底部出现下拉框，直接切换。每套连接各自的邮箱互不影响，切回来还在；编辑不在用的那套不会切换过去；删除要点两次 |
| 语言 | 默认跟随浏览器：中文浏览器显示中文，其他一律英文。设置里可以固定成中文或 English，切换时邮箱和收件状态不受影响 |
| 设置 | 抽屉底部齿轮：外观（跟随系统／亮色／暗色）、语言、唤出快捷键、连接列表（切换、编辑、删除、添加）、重置收件记录、本次不显示、不再在这个网站显示 |
| 出错 | 胶囊状态行写短结论（如「上报失败」），完整原因在抽屉顶部 |

面板显示与邮箱生命周期是两件事：关掉面板不等于关闭邮箱。

## 主域名识别

`for` 由公共后缀列表（含 private suffix）从**唤出时的页面地址**解析，所以：

- `accounts.discord.com` → `discord.com`
- `login.example.co.uk` → `example.co.uk`
- `a.github.io` → `a.github.io`（不会和 `b.github.io` 合并）

识别不出来（`localhost`、IP、内网单段名）时不猜名字，需要你填写服务标识。`chrome://`、`file://` 等非 http(s) 页面不运行。

邮箱一旦创建，它的服务标识就固定了：跳到第三方登录网站、刷新面板都不会改变上报目标。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `GM_xmlhttpRequest` | 用脚本管理器发请求，绕过目标页面的同源限制 |
| `GM_getValue` / `GM_setValue` / `GM_deleteValue` | 保存连接、偏好和本次邮箱状态 |
| `GM_getTab` / `GM_saveTab` | 标记「这个标签页有在用的邮箱」，跳转到别的网站后胶囊能跟过去 |
| `GM_registerMenuCommand` | 菜单入口 |
| `@connect *` | 服务基址由你自己配置，安装时无法预知域名，所以需要通配 |

请求目的地**只**来自你配置的服务基址：路径由脚本拼接，响应若来自别的源会被丢弃；请求带 `redirect: 'error'`，跨源跳转会让请求失败，而不是把 `Authorization` 重放到跳转目标。

## 已知限制

- 页面关闭或浏览器把标签页放到后台后，请求会停止或节流。脚本**不**保证页面关闭后仍在收件；回到页面会重新核对邮箱状态。
- 收件靠单请求长轮询（`wait=true&timeout=20`），一次只有一个请求在跑。
- 同一连接下**多个标签页共享同一个会话**：不会各自取一只邮箱，也不会重复上报（上报前会重读落盘的已上报标记）。但两个标签页同时收件时，后写的一方会覆盖先写的已读列表；需要精确并行时请在同一个标签页里操作。
- 上报 `POST /api/inbox/:id/report` 在上游**不幂等**（会累加统计）。所以已确认成功的邮箱不会重复上报；上报超时会标为「结果待确认」且不自动重放。
- `DELETE /api/inbox/:id` 返回 `ok` 只代表记录已关闭，不代表上游资源清理全部完成。
- 页面（含扩展）理论上能读到面板里已显示的邮箱和验证码 —— Shadow DOM 是样式隔离，不是安全边界。
- 快捷键录制只改变脚本自己的监听，不会改浏览器/扩展层面的按键占用；与网站自身快捷键冲突时以网站为准。
- 只有 Outlook 支持 `selection=matching`；其他提供商按最新邮件处理。
- 打包体积约 300 KiB，主要来自随包打进脚本的公共后缀列表（`tldts`），不依赖页面运行时。
- 不打包字体：装了 Outfit / JetBrains Mono 就用，否则退到系统字体（中文本来就只能用系统字体）。
- 「填入」靠页面给出的线索（type、autocomplete、name、label 等）判断哪个是邮箱框、验证码框；封闭 Shadow DOM 和 iframe 里的输入框找不到，这时会改为复制。

## 更新

服务端在下发脚本时，把 `@updateURL` / `@downloadURL` 和默认服务地址都填成它自己的地址（`src/userscript-route.ts`），所以：

- 装好的脚本从安装它的那台 Mail Hub 检查更新；那台 Mail Hub 升级后，Tampermonkey 会提示更新。
- 脚本版本跟随 `package.json`：只改脚本时也要升版本号，否则 Tampermonkey 不会认为有更新。
- `npm run build` 会顺带构建脚本到 `userscript/mail-hub.user.js`（不进 git），服务启动时读入；没构建过时这个地址返回 404 并提示构建。
- 反向代理后面部署时，按 `X-Forwarded-Proto` / `X-Forwarded-Host` 取对外地址，和 `/v1/llms.txt` 相同；不是普通 http(s) 地址的值会被拒绝（400），不会写进脚本。

GitHub 来源由 `.github/workflows/userscript.yml` 发布：

- 推送 `v*` tag 时构建同一份脚本，只把 `@updateURL` / `@downloadURL` 换成 `userscript` 分支上的 raw 地址，代码里的占位符保留，所以默认服务地址是空的。然后提交到 `userscript` 分支（分支上只有这一个文件）。
- 只有正式 tag 会发布，所以 GitHub 上的脚本不会比已发布的服务端新。tag 必须和 `package.json` 版本一致；分支上已有更高版本时拒绝发布（新安装的人不会拿到旧版）。
- 旧 tag 可以在 Actions 里手动运行这个工作流补发，tag 作为输入。
- 两个来源的 `@name` / `@namespace` 相同，脚本管理器视为同一个脚本：后装的覆盖先装的，更新来源跟着换，不会装出两份。

## 开发

```bash
npm run typecheck:userscript   # tsc -p userscript/tsconfig.json
npm run build:userscript       # 类型检查 + 打包到 userscript/mail-hub.user.js（npm run build 也会做）
npm run preview:userscript     # 本地预览：http://signup.example.localhost:8765/
npx vitest run tests/userscript-*.test.ts
```

本地预览不需要 Tampermonkey 和真 Mail Hub：`dev/serve.mjs` 在内存里提供假的 GM 存储、按标签页存储和 Mail Hub 接口，页面左下角的 dev 条可以模拟来信（验证码、多候选、链接、码+链接、无码邮件）、各接口失败、跳到另一个域名，以及切换表单形态（普通、分格验证码、受控输入、无标签）。连接时服务地址随便填（如 `mail.test`），Key 填任意值。

源码结构：

| 文件 | 职责 |
| --- | --- |
| `src/main.ts` | 菜单、快捷键、初始化与页面生命周期 |
| `src/gm.ts` | GM 请求 / 存储 / 标签页适配，可注入替身 |
| `src/api.ts` | 固定基址、Bearer、响应类型、错误分类 |
| `src/service.ts` | tldts 主域名解析与手动映射 |
| `src/session.ts` | 单邮箱流程、generation 取消、状态落盘 |
| `src/storage.ts` | 配置版本、身份分区、会话恢复、网站偏好 |
| `src/view.ts` | 由落盘状态推导阶段、胶囊内容和抽屉内容（纯函数） |
| `src/fill.ts` | 找页面输入框的打分（纯函数）与写入 |
| `src/panel.ts` | Shadow DOM 胶囊、抽屉、边缘按钮、动效 |
| `src/panel.css` | 沿用后台的颜色/字号/圆角/弹簧动效，亮暗主题、窄屏 |
| `src/icons.ts` | 线性图标 |
| `dev/` | 本地预览服务器与假 GM |
| `src/shortcut.ts` | 快捷键解析、录制与匹配（纯函数） |
| `src/layout.ts` | 面板夹紧、贴边吸附、边缘按钮定位（纯函数） |
| `build.mjs` | 打包单文件并加 userscript 元数据（地址留占位，由服务端下发时填入） |
| `../src/userscript-route.ts` | 服务端：`GET /userscript/mail-hub.user.js`，填入本实例地址 |
| `../.github/workflows/userscript.yml` | 打 tag 时把 GitHub 来源的脚本发布到 `userscript` 分支 |

逻辑测试覆盖服务归属、请求边界与失败分类、生命周期不变量、阶段推导、填入选框；**界面靠真实浏览器截图与操作验证**，不写镜像 DOM 结构的测试。
